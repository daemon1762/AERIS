OBSERVED USER DEFECT
- ND displays a runway that should not be visible and the symbol/pointer follows the aircraft.
- Candidate 7 contains two projection authorities during a GPU FRONT latch:
  1) rendered terrain/world-fixed symbols use AERISTerrainGpuTileRenderer.PresentedProjection;
  2) PreviewRunwayAt hit-testing rebuilt a live requested projection from vessel/PLAN state.
- PreviewRunwayAt ignored the endpoint inside/outside booleans and measured the mouse distance to every projected runway segment.
- Therefore an off-screen runway could be previewed/selected against a projection that was not the currently presented map. Once selected, DrawSelectedRunwayEdgePointer correctly tracks that selected off-scale runway, producing the reported “runway from nowhere that follows me” symptom.

CANDIDATE 8 FIX
- PreviewRunwayAt consumes the same PresentedProjection used by the visible GPU FRONT whenever terrain presentation is active.
- Runway preview candidates must intersect the visible map by exact A/B/center projection.
- A conservative local-distance pre-cull rejects only runways that cannot possibly intersect the viewport.
- Selected runway edge-pointer behavior is retained by bypassing that pre-cull for explicitly selected runways.

PERFORMANCE CHANGES
1. ND runway rendering:
   - one shared AERISNdMapProjection per repaint instead of rebuilding it for A/B/center of every runway;
   - conservative off-screen pre-cull before spherical trigonometric projection.
2. ND instrumentation:
   - terrain tile telemetry snapshot allocation reduced from every Repaint to 2 Hz;
   - GC memory probe reduced to 1 Hz Repaint sampling;
   - Stopwatch object allocation removed from ND draw timing.
3. Map DRAM:
   - unchanged immutable terrain-index wrapper objects are reused;
   - airfield/terrain byte estimates are cached by domain;
   - deterministic sorting removed from DRAM-only publication (persistent manifest remains sorted);
   - routine INDEX_COMMIT INFO logs are coalesced at 64-publish intervals.
4. Terrain preload:
   - the already-existing runtime load-scale policy is now actually applied to background PQS sampling;
   - load shedding changes per-frame throughput only, never tile resolution, LOD, sample data, or GPU presentation quality.
5. Timing probes:
   - AERISTerrainBlockPipeline and GPU renderer/upload timings use Stopwatch.GetTimestamp without per-call Stopwatch allocations.

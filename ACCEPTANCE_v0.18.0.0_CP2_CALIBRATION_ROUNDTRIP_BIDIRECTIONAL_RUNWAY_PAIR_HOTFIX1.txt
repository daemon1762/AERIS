ROOT CAUSE
- ConfigNode.Save/Load can return a named root, a named child below a generic file
  root, or direct values/nodes on a generic root under native KSP/Mono.
- Manual runway calibration verification accepted too narrow a root shape and
  rejected a semantically valid saved file.
- The persistence contract also did not explicitly guarantee that two marked
  endpoints represented one physical runway with two reciprocal operational
  directions.

FIX — DURABLE CALIBRATION ROUND-TRIP
- Resolve all three supported ConfigNode root shapes on load and verification.
- Read back and validate every record from the temporary file before commit.
- Read back and validate the committed final file after atomic move.
- Restore the prior .bak if committed readback fails.
- Persist calibration schema 3 while retaining schema 1/2 migration reads.
- Validate record count, endpoint state, mismatch state and reciprocal-pair data.

FIX — ONE PHYSICAL RUNWAY, TWO RECIPROCAL DIRECTIONS
- MARK A and MARK B persist one physical two-endpoint runway.
- Automatically generate A -> B and B -> A directions.
- Swap Threshold/OppositeThreshold exactly between the two directions.
- Derive headings 180 degrees apart and generate reciprocal runway numbers.
- Require distinct Stable IDs for the two operational directions.
- Publish both direction candidates for independent approach-terrain validation.
- Do not bypass direction-specific terrain/approach safety; one side may fail while
  the opposite side remains certifiable.
- Emit explicit save/readback and reciprocal-pair runtime evidence.

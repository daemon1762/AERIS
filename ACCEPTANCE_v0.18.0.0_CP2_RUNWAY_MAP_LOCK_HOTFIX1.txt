AERIS Flight Control v0.18.0.0 DEV CP2 RUNWAY MAP LOCK HOTFIX 1
================================================================

Purpose
-------
Replace CP2 Closure Candidate 1 after submitted runtime video/log evidence showed
that runway symbols did not remain geographically locked to the rendered terrain.

Submitted-evidence finding
--------------------------
- Island Airfield runway endpoints were rendered from accurate geodetic positions.
- Coarse GPU terrain tiles were stretched into one four-corner screen rectangle.
- Interior terrain features therefore moved relative to runways as map centre,
  heading, range, LOD, Preview/Final and fallback selection changed.
- A secondary residual error was possible because prepared runway tangent-frame
  vectors were subtracted from a live-centre tangent vector.

Implemented correction
-----------------------
- Every GPU terrain vertex retains its exact geographic unit-sphere position.
- Fill, water, contour and coastline vertices are projected from the live ND centre
  with one spherical azimuthal-equidistant projection.
- Four-corner tile rectangles are no longer used as terrain draw transforms.
- Dynamic projected meshes retain CPU access and are marked dynamic.
- Prepared runway symbols retain exact endpoint latitude/longitude.
- Runway draw and mouse hit-testing both project endpoints from the live ND centre.
- Runtime diagnostics identify geometryProjection=SPHERICAL_VERTEX.

Numerical regression model
--------------------------
- The submitted Global-tile rectangle reproduces more than 40 m of runway/terrain
  displacement at the tested Island Airfield reference point.
- The new spherical terrain projection and live runway geodesic agree below 5 cm
  in the independent reference calculation.

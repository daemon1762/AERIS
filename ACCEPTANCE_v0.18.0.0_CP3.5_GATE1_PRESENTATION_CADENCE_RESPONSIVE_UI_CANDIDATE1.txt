GATE 1 PRESENTATION CHANGE
- Removed the Gate 4B forced-recovery full BACK render path.
- FRONT incompatibility now requests a normal BACK refresh but cannot bypass the explicit cadence.
- First-ever FRONT creation is the only cadence bypass.
- ViewGeneration/content revision/movement/heading invalidations all obey the same cadence after the initial attempt.
- Range-aware full-composition cadence:
  - 5/10/20 km: 0.20 s (<=5 Hz)
  - 40 km: 0.25 s (<=4 Hz)
  - 80 km: 0.33 s (<=3.03 Hz)
  - 160 km: 0.50 s (<=2 Hz)
- Compatibility loss is included in refreshRequired, so a moving aircraft schedules the next exact projection rather than waiting only for Terrain/ViewGeneration rollover.
- While waiting, the last complete FRONT is shown without transformation and its exact committed projection remains the common terrain/runway/traffic/ownship authority.
- Telemetry adds forced_recovery_suppressed and back_cadence_s. forced_recovery must remain 0.

USER-REQUESTED UI SPEC CHANGE
- Candidate 9 fixed button geometry is superseded.
- Main AERIS controls scale from window dimensions only.
- Width follows window width continuously using the v0.18 default 520 px window as the baseline proportion.
- Heights follow window height with bounded 0.82x..1.35x scaling.
- Tab row topology remains fixed (3 columns) to prevent threshold-based coordinate jumps.
- Width-threshold scroll/footer/AIRFIELDS chrome switches were removed; those reserves now change continuously with window geometry.
- Automatic word wrapping is prohibited in the active AERISWindow and ND UI styles. Raw AERIS-window skin label/button/toggle/box styles are temporarily forced to no-wrap/clip during the window draw and restored immediately afterward.
- AIRFIELDS selection rows no longer use CalcHeight/content-derived height.
- Long text clips instead of silently changing button geometry.
- Existing screen-space resize pointer anchor, dedicated footer grip and screen clamps remain.

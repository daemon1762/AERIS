3. ROOT CAUSE
AERISNavigationDisplay.CaptureNavigationSnapshot collected runwaySources and facilitySources but did not publish the completed AERISNavigationDisplaySnapshot to AERISNavigationDisplayPipeline through Performance.SubmitNavigationDisplay.

After an airfield reload or manual calibration incremented RunwayDatabaseRevision, the renderer correctly rejected the previously prepared stale frame. Because no replacement snapshot was submitted, no revision-matched frame could be prepared and the ND remained in NAV DATA state. The registry and reciprocal calibration were not lost; the display pipeline publication was missing.

4. IMPLEMENTED CORRECTIONS
- Build and submit an AERISNavigationDisplaySnapshot containing generation stamp, body identity/radius, origin, runway database revision, runway selection revision, runway sources and facility sources.
- Commit capture revision/origin markers only after the scheduler accepts the snapshot.
- Retry a rejected publication after 0.5 seconds instead of falsely suppressing capture for the normal 10-second interval.
- Replace the accumulated full build identity in compact windows with a compact semantic-version/DEV-CP2 title; retain the full identity in logs and build metadata.
- Use wrapped AIRFIELDS status/detail labels and wrapped action buttons.
- Render each runway row as a readable two-line entry and disable horizontal scrolling.
- Default CERTIFIED, PROVISIONAL, FAILED, PENDING and REVALIDATION sections to collapsed.
- Add airfieldsUiLayoutRevision=1 and a one-time migration so existing installations with previously open sections are collapsed on first launch of this build.
- Preserve reciprocal runway-pair calibration, runway recognition/certification, LAND observation-only boundaries, Auto Preload, AP, AA and APP behavior.
- Do not restore old NAV and do not restore CP2 runway-survey debug displays.
